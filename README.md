# 栖伴 Qiban

一个简约、安静的陪伴 Agent：糯米、星弥、曜三种交流风格，共享同一个账号的记忆与成长目标。

**[公开页面](https://saman-max.github.io/qiban-companion-prototype/)** · [后端部署说明](DEPLOYMENT.md)

## 当前状态

仓库包含可运行的真实后端：OpenAI Responses API、账号登录、SQLite 长期记忆、计划建议与到期跟进。**上线真实聊天仍需部署后端，并配置 `OPENAI_API_KEY` 和 `OPENAI_MODEL`。GitHub Pages 只展示前端，不会运行后端。**

GitHub Pages 上的「连接 AI」可打开你部署的陪伴服务。后端同时提供相同的界面和 API，用户在后端地址登录，不会从 GitHub Pages 跨站传输登录凭据。未连接后端时仍可体验原型，界面明确标为演示。已经连接后端时，模型调用失败会显示错误，不会偷偷切回演示回复。

## 运行真实服务

需要 Node.js **24.18.x**，无第三方运行时依赖。

```sh
cp .env.example .env
# 在本地编辑 .env：填写模型密钥和支持 Responses 结构化输出的模型名。
npm start
```

打开 `http://localhost:4173`，创建账号。也可以先不配置模型，验证账号、手动记忆和目标保存；界面会提示「AI 待配置」。注册前不自动上传原型里已有的本地演示数据。

```sh
npm run check
npm test
```

测试使用明确的模型替身验证请求、持久化和错误路径，不需要真实 API Key，不声称验证了真实模型的回复质量。

## 已实现的闭环

- **三款伙伴**：独立人格提示词，共享已确认的长期偏好和目标；对话中切换伙伴不重置记忆。
- **真实对话**：服务器调用 OpenAI Responses API，严格结构化返回；有超时、错误反馈、请求去重与用量限制。
- **长期记忆**：从本轮用户明确表达中提议记忆，保留原文证据；经用户确认后入库。同类偏好可确认替换，支持手动新增、编辑、搜索、删除和导出。
- **记忆召回**：每次对话读取已确认的偏好、相关记忆、完整的当前目标和近期对话。当前版本采用中英文关键词与优先级召回，最多 32 条，不是向量语义检索。
- **目标规划**：结合偏好、可用时间和当前进度，生成 1–6 个带日期和时长的步骤；预览后采用。调整计划保留已完成步骤；进度已变化的旧建议不能直接覆盖新进度。
- **到期跟进**：用户主动开启后，运行中的后端按用户时区检查到期步骤和复盘日期，每天最多一条，数据库去重。页面关闭时保存跟进记录，回来可见；**尚未接入手机/浏览器系统推送**。
- **账号与设备**：同一服务地址、同一账号可跨浏览器使用；记忆和目标使用版本号防止多设备互相静默覆盖。摄像头、语音和示例设备列表仍为演示。

## 数据边界

- 密钥只通过服务器环境变量配置，不进入浏览器、仓库或 GitHub Pages 构建产物。
- 密码用带随机盐的 scrypt 哈希；会话凭据使用 HttpOnly cookie，生产环境强制 HTTPS 配置。
- 每个账号独立保存数据。服务只暴露白名单静态文件，数据库、后端源码和 `.env` 不会被静态服务器提供。
- 对话时，相关记忆、目标和近期上下文会发送给 OpenAI；请求设为 `store: false`。这不等于模型提供方的零数据保留，具体仍取决于 API 账号的数据控制政策。
- 「本次不记忆」不保存该次对话或建议到栖伴数据库，仍会发送当前输入给 OpenAI。限额计数不包含对话文本。
- 编辑或忘记已有记忆，会一并清理旧对话、缓存回复、跟进和未确认建议，避免旧偏好从历史上下文中再次出现；其他已确认记忆和目标保留。
- 数据库需要持久化磁盘和受保护的备份。当前版本适合**单实例部署**，不是多副本分布式数据库架构。

## 文件

| 文件 | 用途 |
| --- | --- |
| `app.js` / `pets.js` / `style.css` | 桌宠与原型交互 |
| `cloud.js` | 同源登录、服务端同步、真实对话及建议确认 |
| `server/index.mjs` | HTTP 服务、认证、接口、限额与来源检查 |
| `server/provider.mjs` | OpenAI 请求、人格、记忆召回、结构化输出校验 |
| `server/store.mjs` | SQLite、版本冲突、记忆/计划落库、持久化跟进 |
| `test/backend.test.mjs` | 后端行为与隔离测试 |
| `.env.example` / `Dockerfile` / `compose.yaml` | 配置与部署 |

## 展示站发布

推送 `main` 后，GitHub Actions 先运行检查与测试，再将白名单前端文件发布到 GitHub Pages。数据库、测试账户、配置密钥和后端源文件不会进入 Pages 发布目录。后端部署需要单独更新并重启，不能靠更新 Pages 启动。
